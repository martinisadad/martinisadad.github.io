Meet Your New Superpower: `einsum`

Welcome, intrepid coder! You're about to unlock one of the most elegant and powerful tools in the numerical computing universe. `einsum` (short for Einstein summation) is a single function that can express a vast array of tensor operations—from simple vector dot products to complex neural network contractions—with a single, concise string. Forget juggling endless functions like `dot`, `multiply`, `transpose`, `sum`, and `reshape`. `einsum` is your Swiss Army knife.

Decoding the `einsum` Spell

The magic of `einsum` lies in a tiny "domain-specific language" string. It's helpful to think of it as a three-step process: (1) element-wise multiplication based on input labels, (2) summing over repeated labels, and (3) ordering the output axes as specified.

'ij,jk' -> 'ik'

Input Labels

Labels on the left of `->` define the input tensors. 'ij,jk' means two 2D tensors.

Summation Indices

A label repeated on the left but not on the right is a summation index. Here, 'j' is summed out.

Free Indices

Labels that appear on both the left and right are free indices. Here, 'i' and 'k' form the output.

The Core Mechanism

For our matrix multiplication example `'ij,jk->ik'`, `einsum` performs an element-wise product between the two input arrays, aligning them on their `j` axes. Then, it sums along this `j` axis. Finally, it ensures the output axes are `i` and `k`. This single, expressive command replaces multiple separate operations.

Advanced Example: Dot-Product Attention

Now let's see `einsum` in a real-world, high-impact scenario: the Scaled Dot-Product Attention mechanism, a cornerstone of Transformer models. This function uses `einsum` twice to perform the core computations with remarkable clarity and efficiency.

The high-level goal is to calculate how much each word (query) should "pay attention to" every other word (key) in a sequence, and then produce a new representation for each word based on a weighted sum of all word values.

The Code

import jax
import jax.numpy as jnp
from typing import Optional

def dot_attention(
    query: jax.Array, 
    key: jax.Array, 
    value: jax.Array, 
    atten_mask: Optional[jax.Array] = None
) -> tuple[jax.Array, jax.Array]:
    """Calculate the attention weights.
    
    Args: Using the notation b = batch_size, n = num_heads, s = sequence length 
       of key and value, t = sequence length of query, h = dimension of heads, 
       the arguments of the shape must be as follows: 
           q: query shape == [b, n, t, h] 
           k: key shape   == [b, n, s, h] 
           v: value shape == [b, n, s, h] 
           mask: Float tensor with shape broadcastable to [..., t, s]. Defaults 
           to None. 

    Returns: 
       output with shape [b, n, t, h] 
       attention_weights with shape [b, n, t, s]
    """
    b, n, s, h = key.shape
    t = query.shape[2]
    
    # (Assuming a helper function 'assert_has_shape' exists for clarity)
    assert_has_shape(value, [b, n, s, h]) 
    assert_has_shape(query, [b, n, t, h]) 

    # 1. Dot product of Query and Key to get raw scores (logits)
    logits = jnp.einsum('BNTH,BNSH->BNTS', query, key)
    assert_has_shape(logits, [b, n, t, s])
    
    # 2. Scale the logits
    scaled_attention_logits = logits / jnp.sqrt(h)
    
    # 3. Apply mask (optional)
    if atten_mask is not None:
      scaled_attention_logits += atten_mask
      
    # 4. Normalize scores into weights
    attention_weights = jax.nn.softmax(scaled_attention_logits, axis=-1)
    
    # 5. Multiply weights by Value to get final output
    output = jnp.einsum('BNTS,BNSH->BNTH', attention_weights, value)
    assert_has_shape(output, [b, n, t, h])
    
    return output, attention_weights

Step-by-Step Breakdown

Step 1: Calculate Raw Similarity Scores (Logits)

This is the heart of the "dot-product" part. We use `einsum` to calculate the similarity between every query vector and every key vector.

logits = jnp.einsum('BNTH,BNSH->BNTS', query, key)
  • Inputs: Query (`BNTH`) and Key (`BNSH`).
  • Operation: `einsum` performs a dot product along the matching head dimension (`H`). `B` (batch) and `N` (heads) are treated as batch dimensions.
  • Output: The result (`BNTS`) contains the raw similarity score for each query (`T`) against each key (`S`).

Step 2: Scaling the Scores

This is the "Scaled" part. Dot product scores can become very large, which can destabilize training. To counteract this, we scale them down by the square root of the head dimension (`h`).

scaled_attention_logits = logits / jnp.sqrt(h)

Step 3: Applying the Mask (Optional)

Masking is crucial for ignoring irrelevant parts of the sequence, such as padding tokens or, in decoders, future tokens (to prevent "cheating"). The mask adds a large negative number to the logits you want to ignore, making their scores effectively zero after the softmax.

if atten_mask is not None: scaled_attention_logits += atten_mask

Step 4: Normalizing Scores into Weights

The softmax function converts the scaled, masked scores into a probability distribution along the key/source sequence length axis (`S`). For each query, the sum of its attention weights across all keys will now equal 1.

attention_weights = jax.nn.softmax(scaled_attention_logits, axis=-1)

Step 5: Producing the Final Output

Finally, we use the attention weights to create a weighted sum of the `value` vectors. This is the second key use of `einsum`.

output = jnp.einsum('BNTS,BNSH->BNTH', attention_weights, value)
  • Inputs: Attention Weights (`BNTS`) and Value (`BNSH`).
  • Operation: For each query (`T`), this multiplies its attention weights with the corresponding value vectors and sums the results up along the `S` dimension.
  • Output: The final output (`BNTH`) is a contextualized embedding for each query, containing information from the entire value sequence, weighted by relevance.

The `einsum` Advantage

So, why should you adopt this new superpower? `einsum` offers a trifecta of benefits that make your code cleaner, more flexible, and often faster. This is especially true in a framework like JAX, where `einsum` can be Just-In-Time (JIT) compiled and optimized.

📖Readability

`einsum` strings are self-documenting. `'bij,bjk->bik'` is instantly recognizable as batch matrix multiplication to those familiar with the notation, which is cleaner than a chain of transposing, reshaping, and multiplying calls.

🤸Flexibility

One function to rule them all. Need to multiply, sum, and transpose in one go? No problem. `einsum` handles it in a single, atomic operation, reducing intermediate arrays and mental overhead.

🚀Efficiency

By combining operations, `einsum` often avoids creating large intermediate arrays. This saves memory and can be significantly faster than chaining multiple separate function calls, reducing Python overhead.
